----------------------------------------------------------------
[프로젝트 개요]
----------------------------------------------------------------
반려동물 입양 전 추천부터 평생 관리까지 하나의 앱에서 제공하는
한국 타겟 모바일 앱 (React Native + Expo).

타겟: 반려동물을 처음 키우거나 체계적 관리가 필요한 20~40대 한국인
플랫폼: iOS + Android (단일 코드베이스)

----------------------------------------------------------------
[현재까지 완료된 작업]
----------------------------------------------------------------

1. 서비스 구조 설계 (사업 전문가 관점)
   - 전체 서비스 플로우 확정
   - Phase별 장단점 분석
   - 경쟁사 포지셔닝 (펫닥, 마이펫닥터, 펫프렌즈, 동물보호관리시스템)

2. 수익 모델 확정
   원칙: 무료 유저에게도 광고 없음. 구독은 강제가 아닌 선택.
   1순위: 네이티브 커머스 어필리에이트 (케어 플로우 안에 자연스럽게 녹인 추천)
   2순위: B2B 제휴 (동물병원, 펫보험사, 사료 브랜드)
   3순위: 선택적 프리미엄 구독 (월 1,900원, v2.5 이후 도입)

   프리미엄 혜택:
   - 반려동물 등록: 무료 1마리 / 프리미엄 무제한
   - 사진 다이어리: 무료 500MB / 프리미엄 무제한
   - 건강 리포트: 무료 없음 / 프리미엄 월간 PDF
   - 광고: 무료/프리미엄 모두 없음

3. 설문 문항 설계 (7문항, 한 화면에 한 문항씩)
   Q1. 거주 형태 (소형 아파트 / 대형 아파트 / 주택 마당 없음 / 주택 마당 있음)
   Q2. 하루 집에 있는 시간 (항상 / 4~6시간 / 저녁에만 / 출장 잦음)
   Q3. 보호자 활동량 (집순이 / 가끔 산책 / 매일 운동)
   Q4. 반려동물 경험 (처음 / 오래됨 / 있음 / 많음)
   Q5. 월 예산 (5만원 이하 / 5~15 / 15~30 / 30만원 이상)
   Q6. 가족 구성 (영유아·어린이 / 노인 / 성인만 / 알레르기) — 복수 선택
   Q7. 털 빠짐 허용 (상관없음 / 적당히 / 최소화 / 거의 없는 견종)

4. 견종 추천 로직 확정
   방식: 실시간 Claude API 호출 X → 사전 정의 데이터 기반 스코어링
   이유: 일관성 확보, API 비용 없음, 즉시 반환, 장애 무관
   Claude API 역할: 개발 시 견종 특성 수치화에만 1회 사용

5. 생성된 파일 목록
   - pet-care-app/CLAUDE.md          ← 전체 프로젝트 스펙 문서 (핵심)
   - pet-care-app/types/breed.ts     ← 타입 정의
   - pet-care-app/data/breeds.ts     ← 견종 20종 특성 데이터
   - pet-care-app/lib/recommendation.ts ← 스코어링 알고리즘

6. 견종 데이터 (breeds.ts) — 20종 수록
   소형견 (10종): 말티즈, 토이푸들, 포메라니안, 치와와, 시츄,
                  비숑프리제, 닥스훈트, 요크셔테리어, 파피용, 스피츠
   중형견 (6종):  비글, 웰시코기, 시바이누, 프렌치불도그, 진돗개, 보더콜리
   대형견 (4종):  골든리트리버, 래브라도리트리버, 시베리안허스키, 사모예드

   스코어링 기준 (1~5점):
   - size (1=소형, 3=대형)
   - activityLevel, shedding, groomingNeeds
   - childFriendly, aloneTolerance
   - apartmentFit, beginnerFriendly
   - monthlyCostMin/Max, allergyFriendly, adoptable

7. 기능 목록 확정
   ✅ 설문 기반 견종 추천
   ✅ 반려동물 프로필 등록
   ✅ 일상 케어 리마인더 (밥, 약, 병원, 귀청소, 목욕, 발톱)
   ✅ 사진 다이어리
   ✅ 산책 기록 (GPS 거리·시간·사진)
   ✅ 여행지 커뮤니티 (v2.5, UGC 방식)
   ❌ 급여량/칼로리 기록 — 복잡도 이유로 제외 결정

8. 출시 로드맵
   v1.0 MVP (8주):  설문 추천 + 프로필 등록 + 리마인더 + 사진 다이어리
   v1.5  (+4주):    분양처 연결 (animal.go.kr API) + 산책 기록
   v2.0  (+6주):    네이티브 커머스 추천 + 어필리에이트 본격화
   v2.5  (+6주):    B2B 병원·보험 제휴 + 프리미엄 구독 + 여행지 커뮤니티

----------------------------------------------------------------
[기술 스택]
----------------------------------------------------------------
모바일:     React Native + Expo
언어:       TypeScript
상태관리:   Zustand
백엔드:     Supabase (PostgreSQL + Auth + Storage)
AI 추천:    Claude API claude-sonnet-4-6 (개발 시 1회)
알림:       Expo Notifications + Firebase FCM
외부 API:   동물보호관리시스템 (animal.go.kr)
지도 (v2.5): 카카오맵 또는 네이버맵 API
결제:       토스페이먼츠 또는 카카오페이

----------------------------------------------------------------
[주요 결정 사항 & 이유]
----------------------------------------------------------------
- 구독 전에 광고 없음: 한국 유저의 구독 거부감 + 감성 앱에서 광고는 신뢰 훼손
- 급여량 기록 제외: 영양 DB 구축·칼로리 계산 로직 등 복잡도 대비 효과 낮음
- 사진 제한을 장수가 아닌 용량(500MB)으로: 장수 제한은 이탈 요인, 용량은 체감 덜함
- 여행지를 v2.5로 후순위: UGC는 콘텐츠 관리·어뷰징 대응 등 운영 비용이 크므로
- Claude API 런타임 미사용: 일관성, 비용, 속도 모두 사전 데이터 방식이 우월
